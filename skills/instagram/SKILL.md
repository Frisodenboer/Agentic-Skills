# Instagram — Post/Story/Reel Sizing

Take an existing image (typically artwork already generated by one of this project's art skills) and produce Instagram-ready crops at Instagram's exact recommended pixel dimensions. This skill only formats images that already exist — it doesn't generate new artwork. If the user wants new art made *and* Instagram-ready, generate it first with the relevant art skill, then hand the result to this skill.

## Size reference

Full detail (including the "minimum resolution" framing, profile-photo circular safe area, and the 4:5 vs 3:4 vertical choice) is in `references/instagram-specs.md`. Read it before a first-time formatting job so the numbers and reasoning are fresh — the condensed table:

| Format | Dimensions | Aspect ratio |
|---|---|---|
| Profile photo | 320 × 320 px | 1:1 |
| Square feed post | 1080 × 1080 px | 1:1 |
| Vertical feed post (default) | 1080 × 1350 px | 4:5 |
| Vertical feed post (alt) | 1080 × 1440 px | 3:4 |
| Horizontal feed post | 1080 × 566 px | 1.91:1 |
| Story | 1080 × 1920 px | 9:16 |
| Reel cover/thumbnail | 1080 × 1920 px | 9:16 |

## Workflow

### 1. Identify the source image and target format(s)

Ask for (or confirm from context) which existing image file to format. Ask which Instagram format(s) are wanted — square, vertical (4:5 default, offer 3:4 as an alternative), horizontal, story/reel, profile, or all of the main set at once. Default to **square + vertical + story** if the user just says "make this Instagram ready" without specifics — that covers feed and Stories, the two most common posting surfaces.

**The source must be the unsigned artwork — the NOOL signature must never appear in Instagram content.** If given a file from `public/Artwork/` whose name indicates it's signed (e.g. `nool-*-signed.jpg`), don't use it directly — find or produce the pre-signature version instead (the resized-but-unsigned file from the art skill's own workflow, typically still sitting in `public/generated-images/`). If only a signed file is available and no unsigned original can be found, say so and ask rather than formatting the signed file anyway.

### 2. Decide crop vs. pad

This project's art skills mostly output 16:9 (3840×2160), which doesn't natively match any Instagram format. Every target format needs either a crop (cut to fit) or a pad (shrink to fit, fill the rest). Read the "Choosing crop vs. pad for artwork" section of `references/instagram-specs.md` and make a call based on the actual composition:

- **Crop** (default) — good when the subject is centered or off to one side with room to spare (most single-hero-motif pieces, e.g. Pen-Coastal's object studies). Use `--focus-x`/`--focus-y` (0.0-1.0) to bias the crop toward where the subject actually sits if it's not centered — e.g. a subject in the left third of a 16:9 image needs `--focus-x 0.0` or similar when cropping down to a square, or the crop will center on empty background instead.
- **Pad** — good when the composition is wide/panoramic or busy edge-to-edge (landscape pieces, vignette-grid compositions) where cropping would cut off part of what makes the piece work. `--pad-style blur` (default) fills the letterbox with a blurred, cover-scaled version of the same image so it doesn't look like a hard border; `--pad-style color` fills with a flat color via `--pad-color` if the user wants a cleaner mat/frame look instead.

Look at the actual image before deciding — don't default blindly to crop for every piece. If unsure, say what you're seeing and ask.

### 3. Run the formatting script

```bash
cd "C:/Claude Code Projects/Art Project" && python .claude/skills/instagram/scripts/format_for_instagram.py \
  --image "<path-to-source-image>" \
  --format <profile|square|landscape|portrait|portrait-3-4|story|reel|all> \
  --mode <crop|pad> \
  --focus-x <0.0-1.0, crop mode only, default 0.5> \
  --focus-y <0.0-1.0, crop mode only, default 0.5> \
  --pad-style <blur|color, pad mode only, default blur> \
  --pad-color "<hex, pad mode + color style only, default #FFFFFF>"
```

Run it once per format if different formats need different crop/pad choices for the same source (e.g., square crops fine but story needs padding) — the script only applies one mode per invocation. Use `--format all` when every main format should use the same crop/pad treatment.

The script saves everything to `public/instagram/<YYYY-MM-DD>/`, named `<source-name>-ig-<format>-<dimensions>.jpg`, and prints each output's path, dimensions, and file size.

### 4. Present the result

Show the user each generated file's path, dimensions, and file size. If a crop looks like it might have cut off something important, or a pad's letterboxing looks awkward, say so and offer to re-run with a different focus point, mode, or pad style rather than presenting a bad crop as final.

## Tips

- **This skill formats, it doesn't generate.** If there's no source image yet, point the user to (or invoke) the relevant art-generation skill first.
- **Look before you crop.** A blind center-crop on a 16:9 image turned into a 9:16 Story will usually lose most of the image — always check where the subject actually sits and set `--focus-x`/`--focus-y` accordingly, or switch to pad mode.
- **Square post is what the grid crops everything down to anyway** — when producing multiple formats from one source, sanity-check that the square version alone would still read as a complete composition, since that's what most viewers see first while scrolling.
- **The dimensions in the reference table are minimums, not caps** — always export at exactly the listed size (not smaller), since Instagram will upscale and soften anything under it.
- **Vertical feed posts have two valid ratios (4:5 and 3:4)** — default to 4:5 unless the user specifically wants the slightly taller 3:4 variant.
- **Never format the signed portfolio copy for Instagram.** This project signs finished artwork with the NOOL signature (`public/Artwork/nool-*-signed.jpg`) for portfolio/gallery use only — Instagram exports, like Adobe Stock exports, must stay unsigned. Always source from the pre-signature file. If a signed file crops/pads in a way that would put the signature in frame, that's doubly a reason to redo it from the unsigned source rather than accept it.
